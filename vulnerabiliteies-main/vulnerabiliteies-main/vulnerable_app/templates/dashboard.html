Command Injection

CRÍTICO · A03:2021

Ejecución de comandos del SO mediante input no sanitizado.

¿Cómo funciona? El endpoint /ping ejecuta ping -c 1 {host} con shell=True. Los operadores ; && | permiten encadenar comandos arbitrarios con acceso RCE completo.

Test CMDi — /ping

Prevención

✗ subprocess.run(f"ping {'{host}'}", shell=True)
✓ subprocess.run(["ping","-c","1", host])
✓ Validar host con regex ^[\d.]+$
✓ Lista blanca de hosts permitidos

File Upload sin validación

A05 · Misconfiguration

El servidor acepta cualquier archivo sin validar extensión, MIME ni tamaño.

Tres vulnerabilidades en uno: Sin filtro de extensión (acepta .py, .sh, .php), path traversal con filenames como ../../../etc/cron.d/backdoor, y sin límite de tamaño (posible DoS).

Subir archivo — /upload

Path Traversal

upload_output

Remediación

✗ save_path = os.path.join(UPLOAD_DIR, f.filename)
✓ filename = secure_filename(f.filename)
✓ Validar extensión contra lista blanca
✓ Verificar MIME real con python-magic
✓ Limitar tamaño con MAX_CONTENT_LENGTH

Deserialización insegura

CRÍTICO · A08:2021

pickle.loads() ejecuta código arbitrario al deserializar objetos no confiables.

¿Por qué pickle es peligroso? Ejecuta el método __reduce__ al deserializar. Un atacante que controla el payload puede hacer que el servidor ejecute cualquier comando — RCE completo, equivalente a Command Injection.

Generar payload RCE

Enviar al servidor — /deserialize

deserialize_output — RCE via pickle

Comando para generar el payload

python3 -c "
import pickle, os, base64
class RCE:
  def __reduce__(self): return (os.system, ('id',))
print(base64.b64encode(pickle.dumps(RCE())).decode())
"

Sin Logging de Seguridad

ALTO · A09:2021

/admin no registra intentos. Compara con /admin-safe que sí genera logs.

¿Cuál es el riesgo? Sin logging, los ataques de fuerza bruta y accesos no autorizados pasan completamente desapercibidos. La media de detección sin logging es más de 200 días.

Fuerza bruta /admin (sin logs)

Prueba múltiples passwords — ninguno quedará registrado.

Fuerza bruta /admin-safe (con logs)

Mismo ataque — cada intento queda en /tmp/security.log.

SSRF — Server-Side Request Forgery

ALTO · A10:2021

El servidor realiza peticiones a URLs del usuario sin validar host ni esquema.

¿Qué permite SSRF? El atacante usa el servidor como proxy para acceder a servicios internos, endpoints de administración, metadata cloud (AWS/GCP/Azure) y archivos locales. En cloud puede conducir a robo de credenciales IAM.

Payloads SSRF — /fetch?url=

Impacto por escenario

URL Impacto
/infoSecret key → forjar sesiones
/api/usersDatos de todos los usuarios
file:///etc/passwdUsuarios del SO
169.254.x.xCredenciales IAM cloud

Remediación

✗ Listas negras de IPs (siempre bypass)
✓ Lista blanca de dominios permitidos
✓ Solo esquema https://
✓ allow_redirects=False
